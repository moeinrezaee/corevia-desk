# استاندارد مستندات Corevia Desk

آخرین به‌روزرسانی: ۲۰۲۶-۰۹-۰۵
مالک: Platform Engineering
وضعیت: فعال
نسخه: ۱.۰.۰

## هدف

مستندات Corevia Desk باید برای انسان، عامل هوش مصنوعی و Validatorهای Corevia بدون وابستگی به تاریخچه‌ی چت قابل استفاده باشد.

## محدوده

این استاندارد Markdown، OpenSpec، TestSpec، رودمپ، Evidence، تاریخچه‌ی مشکل، انتشار و handoff همین مخزن را پوشش می‌دهد.

## پیش‌نیاز

- `docs/INDEX.fa.md` را بخوان.
- قبل از ادامه، `docs/evidence/current-status.fa.md` و `docs/handoff/next-context.fa.md` را بخوان.
- قبل از هر عملیات تکرارشونده‌ی بیرونی، Pattern مناسب Corevia Standards را مشخص کن.

## پیکربندی

- سند انگلیسی و فارسی باید به‌شکل `<name>.md` و `<name>.fa.md` جفت باشند.
- Secretهای Runtime فقط در Secret Store یا متغیرهای محرمانه‌ی CI باشند.
- Values سورس‌محور باید declarative و بدون بایت Secret باشند.
- وضعیت‌ها را با `complete`، `in_progress`، `pending`، `blocked` و `deferred` یکدست بنویس.

## اجرا و استفاده

برای پیدا کردن مرجع از Index استفاده کن. هر تغییر رفتار یا راستی‌آزمایی باید هم‌زمان اسپک و Evidence مربوط را به‌روز کند. برای کانتکست خالی از سند handoff استفاده کن.

## اعتبارسنجی

- بررسی جفت انگلیسی/فارسی و لینک دوطرفه.
- بررسی بخش‌های لازم و لینک‌های محلی.
- بررسی نبود Secret خام.
- Validator مخزن Corevia Standards.
- `git diff --check`.
- Evidence باید فرمان، هدف، نتیجه و تاریخ را بدون افشای Credential ثبت کند.

## رفع اشکال

- اگر دو سند اختلاف داشتند، Evidence تأییدشده بر برنامه مقدم است و هر دو زبان را اصلاح کن.
- اگر چیزی فقط قرارداد یا Plan محلی است، آن را باز نگه دار و تحویل‌شده اعلام نکن.
- اگر Executor بریج وجود ندارد، `extension-needed` ثبت کن و Mutation دستی بیرونی انجام نده.
- اگر Runner بومی در دسترس نیست، هدف را باز نگه دار و کار امن محلی را ادامه بده.
