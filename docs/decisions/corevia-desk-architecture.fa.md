# تصمیم معماری Corevia Desk

## وضعیت

برای مبنای رودمپ در تاریخ ۲۰۲۶-۰۹-۰۲ پذیرفته شد.

## مسئله

Corevia Desk هم‌اکنون هسته‌ی Rust و منابع رابط بومی به‌جامانده را دارد. محصول جدید به رابط وب، کنترل MCP، دو پروفایل دسترسی و بسته‌های دسکتاپ چندسکویی نیاز دارد؛ بدون اینکه منطق Rust دوباره‌کاری شود. مسیر فعال محصول نباید به Flutter یا Dart وابسته باشد.

## گزینه‌ها

### گزینه A — فعال نگه‌داشتن رابط بومی به‌جامانده

کم‌ریسک‌ترین مسیر کوتاه‌مدت است، چون منابع رابط بومی فعلی وجود دارند. اما طراحی HTML/Tailwind باید در یک فناوری رابط دیگر دوباره ساخته شود و منبع طراحی وب مستقیماً قابل استفاده نخواهد بود.

### گزینه B — ساخت لایه‌ی Nuxt داخل Corevia Desk با پوسته‌ی WebView مبتنی بر Rust

رابط Nuxt می‌تواند از قالب تأییدشده‌ی `corevia-desk-ui` ساخته و برای دسکتاپ بسته‌بندی شود، درحالی‌که Rust هسته‌ی دسترسی سیستم و دسکتاپ راه دور باقی می‌ماند. این گزینه به پل جدید Nuxt و Rust نیاز دارد، اما مرز مسئولیت‌ها را روشن نگه می‌دارد و مسیر آینده‌ی موبایل را باز می‌گذارد.

### گزینه C — پوسته‌ی دسکتاپ مبتنی بر Electron

استفاده از رابط وب را برای Windows، macOS و Linux آسان می‌کند، اما یک Runtime دسکتاپ جدا اضافه می‌کند و مسئله‌ی موبایل را حل نمی‌کند. همچنین یک مرز اضافه بین هسته‌ی Rust و پوسته‌ی برنامه ایجاد می‌شود.

## تصمیم

گزینه B انتخاب شد.

- Rust همان منبع اصلی دسترسی سیستم و رفتار دسکتاپ راه دور باقی می‌ماند.
- یک ACL اجباری و لایه‌ی مشترک دستورات در Rust به رابط فعال Nuxt/WebView و MCP سرویس می‌دهد.
- منبع خام طراحی `corevia-desk-ui` باقی می‌ماند.
- پیاده‌سازی Nuxt داخل `corevia-desk/web` انجام می‌شود و باید از Atoms، Molecules، Organisms، Templates، Layouts و Pages پیروی کند.
- آداپتور MCP داخل `corevia-desk/mcp` قرار می‌گیرد و فقط به لایه‌ی مشترک Rust وصل می‌شود؛ نه به پل رابط‌های قدیمی و نه مستقیماً به توابع سطح پایین Rust.
- رابط فعال دسکتاپ، Nuxt داخل WebView بومی Rust است. منابع قدیمی Flutter/Dart و Sciter فقط برای حفظ تاریخچه و امکان Rollback نگه داشته می‌شوند و وارد Build، CI، Installer یا Release فعال نیستند. کار موبایل تعویق دارد.
- Host بومی در `src/webview.rs` با `tao` و `wry` پیاده‌سازی شده است؛ assetهای Nuxt بسته را از پروتکل خصوصی `corevia://` می‌دهد و Bridge نام‌گذاری‌شده را از مسیر ACL Rust عبور می‌دهد.
- CI/CD متعلق به Corevia Desk دو پروفایل انتشار را برای هر محیط می‌سازد و در Nexus منتشر می‌کند.
- در صورت توسعه‌ی آینده‌ی Corevia Installer، فقط پروفایل Customer Support را مصرف می‌کند.
- Corevia Bridge فقط مالک نصب عملیاتی تأییدشده، سلامت، به‌روزرسانی، Rollback و تنظیمات Runtime است.

## پیامدها

- فاز سه باید پیش از expose شدن قابلیت‌های Nuxt یا MCP، ACL Rust را ایجاد کند.
- فاز چهار باید منبع طراحی تأییدشده را به سیستم واقعی کامپوننت‌های Nuxt تبدیل کند، نه یک رابط دوم و بی‌ارتباط.
- منابع رابط قدیمی در دوره‌ی مهاجرت حفظ می‌شوند تا تاریخچه و مدرک Rollback موجود باشد؛ اما این موضوع نصب یا اجرای Flutter/Dart را توجیه نمی‌کند.
- اولویت خروجی با دسکتاپ چندسکویی است و موبایل مانع ادامه‌ی رودمپ نیست.
