# نمای کلی محصول Corevia Desk

آخرین به‌روزرسانی: ۲۰۲۶-۰۹-۰۵
وضعیت: فعال
مالک: Platform Engineering

## هدف

Corevia Desk محصول ریموت‌دسکتاپ برند Corevia است که بر یک Rust Core، رابط Nuxt داخل WebView بومی و یک سطح کنترل MCP حاکمیت‌شده بنا شده است.

## محدوده

این مخزن Runtime ریموت‌دسکتاپ Rust، رابط فعال Nuxt، ACL و Bridge مشترک Rust، دو پروفایل انتشار، کد Policy/Catalog مربوط به MCP و بسته‌بندی انتشار را دارد.

منبع خام طراحی در sibling به نام `corevia-desk-ui` باقی می‌ماند و رابط اجرایی در همین مخزن و مسیر `web/` پیاده می‌شود. `corevia-web` منبع رابط این محصول نیست.

## پروفایل‌های محصول

| پروفایل | سطح مجاز محصول | توزیع |
| --- | --- | --- |
| Full Desk | همه‌ی قابلیت‌های تأییدشده‌ی ریموت‌دسکتاپ، با ACL و تأیید | Artifact جدا برای macOS، Windows، Linux و خروجی Docker لینوکس در Nexus |
| Customer Support | فقط تنظیمات مشتری، تأیید اتصال ورودی و مجوزهای اتصال | Artifact جدا برای macOS و Windows؛ Installer مشتری فقط در صورت نیاز |

هر دو پروفایل از Rust Core و ACL مشترک استفاده می‌کنند. تفاوت پروفایل فقط با مخفی‌کردن دکمه پیاده نمی‌شود و باید در Policy Rust، سطح UI، Catalog MCP و Metadata انتشار اعمال شود.

## مسیر Runtime فعال

```text
Rust Core -> Rust ACL -> Host بومی WebView -> رابط Nuxt با طراحی اتمیک
                         \-> Adapter حاکمیت‌شده‌ی MCP
```

مسیر اتصال محصول ID/Relay راست‌دسک است و دو دستگاه لازم نیست در یک شبکه باشند. تست با IP یا هم‌شبکه‌بودن Evidence قابل قبول نیست.

## خارج از Scope فعال

- Flutter و Dart در UI دسکتاپ، CI، Installer یا Release فعال استفاده نمی‌شوند.
- Sciter فقط به‌عنوان تاریخچه‌ی سورس و مرجع Rollback حفظ شده است.
- موبایل تعویق دارد و نباید تحویل دسکتاپ را متوقف کند.
- افزونه‌ی Docker برای VS Code در آینده و با اولویت بسیار پایین است و گیت انتشار نیست.

## انتظار از State و داده

دستگاه‌ها، نشست‌ها، اتصال‌های اخیر، تنظیمات، نشست‌های هم‌زمان، Clipboard، Toolbox، واکنش‌گرایی و قرینه‌سازی دقیق RTL/LTR نیاز محصول هستند. Fixture، کارت ثابت یا صرفاً بازشدن صفحه ثابت نمی‌کند قابلیت واقعی است. ماتریس پذیرش هر مورد را جداگانه ثبت می‌کند.
