# تاریخچه‌ی تغییرات اسپک Corevia Desk

## ۲۰۲۶-۱۰-۰۸

- موجودی‌گیری فقط‌خواندنی Windows با WinRM و رمزگذاری پیام NTLM موفق شد: Windows Server 2025 Standard Evaluation x64، درایو C با حدود ۱۱۹ GiB ظرفیت و ۱۵ GiB فضای آزاد، بدون volume شخصی، سرویس Corevia Desk نسخهٔ 1.5.0 و پردازهٔ Customer Support نسخهٔ 1.5.0 در نشست قطع‌شدهٔ ۲. این فقط شاهد دسترسی به میزبان است، نه قبولی UI/تصویر محصول. اثرانگشت گواهی خودامضای RDP در Windows App با مقدار خوانده‌شده از Listener سرور دقیقاً برابر است. «Always trust» خاموش ماند و هشدار پیش از واردکردن گذرواژه لغو شد؛ هیچ تغییری روی سرور انجام نشد. [شواهد](../evidence/corevia-desk-windows-winrm-readback-20261008.fa.md). تلاش اول به‌دلیل XML parser محلی شکست خورد؛ Python همراه Codex در Readback بعدی پاسخ داد.
- بلاکر زنده، تأیید یک‌باره برای ادامه از گواهی خودامضای تطبیق‌داده‌شده و دسکتاپ تعاملیِ جداست؛ روی Worker volume شخصی یا Docker service پیدا نشد، پس Docker روی C اجرا نشد.

Plan رسمی هنوز Update هر دو فایل را پیشنهاد می‌کند؛ Apply دیگری انجام نشد و خود الگو همچنان نیازمند اصلاح است.
- درخواست زندهٔ Peer ID پس از نرسیدن تأیید همان‌لحظه رد شد؛ هیچ تصویر یا ورودی‌ای منتقل نشد و Readback نشست‌ها Active=0 را نشان داد. ظرفیت آزاد هر دو volume حدود ۴۲ GiB است.

- باندل دقیق و جاری Customer Support پس از درخواست خودش و راه‌اندازی مجدد دوباره تست شد: تنظیمات macOS ورودی‌های صفحه/صدا را روشن نشان می‌دهد، اما برنامه هنوز تصویر را غیرفعال می‌خواند. مجوز مالک برای شاهد جایگزین Windows معتبر است؛ TCC reset یا امضا دور زده نشد. آزمون‌های سبک دوباره پاس شدند: Web ‏۱۵/۱۵، MCP ‏۲۷/۲۷، Release ‏۱۰/۱۰ و lintهای Atomic/Profile؛ ممیزی رسمی مستندات Standards نیز برای ۵۳ فایل بدون finding پاس شد. کش قابل‌بازسازی Cargo Corevia Desk از مسیر مالک با `cargo clean` پاک شد (۵٫۵ GiB) و کش قدیمی فهرست افزونه‌های Codex نیز حدود ۷۷ MiB پاک کرد؛ باندل‌های جاری و Docker حفظ شدند و اکنون حدود ۳۸ GiB فضای آزاد داریم.
- بررسی مسیر رسمی دسترسی ویندوز: Validate و Plan استانداردها در همین مک، بدون اتصال به سرور یا تغییر وضعیت، پاس شدند. الگوی منطبق Bridge هنوز آزمایشی است و HTTP/5985 با Basic و بررسی گواهی خاموش را اجباری می‌کند؛ اجرا نشد. امضای مک بلاکر نیست؛ پذیرش جایگزین ویندوزی هنوز مسیر رسمیِ امن و دسکتاپ تعاملیِ جدا می‌خواهد. [شواهد](../evidence/corevia-desk-windows-safe-access-20261008.fa.md).
- مسیر دقیق باندل تازه از تنظیمات macOS اضافه شد و هر دو ورودی Corevia Desk روشن‌اند، اما راه‌اندازی دوباره ابتدا نسخهٔ قدیمی را باز کرد. بعد از بستن عادی آن و اجرای باندل فعلی، تصویر همچنان در دسترس نبود و درخواست رسمی مجوز هم تغییری نداد. امضای ad-hoc CDHash-محور است؛ [مستند Apple](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements) وابستگی شرط آن به همان نسخه را توضیح می‌دهد، اما علت قطعی نیست.
- مرز امن تست ورودی: روی باندل قدیمیِ مجازشدهٔ Customer Support اجازهٔ کیبورد/ماوس برای یک نشست پذیرفته شد، اما ورودی ارسال نشد. صفحهٔ مقصد محتوای شخصی مرورگر را داشت، بنابراین تست فوراً متوقف، ورودی خاموش و نشست بسته شد. Clipboard/فایل/صدا/ترمینال/MCP/Toolbox اجرا نشدند؛ پذیرش ابزارهای زنده باز است و به دسکتاپ آزمایشی جدا نیاز دارد.
- Readback بومی تازه: Customer Support جاری هنوز ضبط تصویر را در دسترس نمی‌داند و درخواست ورودی ندارد؛ Sessions در Full Desk Active=0 است. Devices در مجموع دو دستگاه ذخیره‌شده دارد: یک ردیف برای Peer مکِ چندباراستفاده‌شده (آخرین اتصال ۷ اکتبر، ۲:۰۷ بعدازظهر) و یک Peer قدیمی Windows. تاریخچه نشست پایان‌یافته و تلاش ناموفقِ جداگانه با شناسهٔ آزمایشی را دارد؛ اتصال‌های تکراری به یک Peer ID ردیف دستگاه تکراری نساختند.
- بررسی اولیهٔ مسیر امن Windows: TCPهای 3389/5985 پاسخ دادند و 5986/22 نه. گواهی خودامضای RDP مورداعتماد قرار نگرفت. Validate و Plan رسمی بدون اتصال پاس شدند، اما اجراگر آزمایشی Bridge، HTTP Basic و بررسی گواهی خاموش را اجباری می‌کند؛ اجرا نشد. در همان بررسی هیچ فرمانی به میزبان نرفت؛ موجودی‌گیری WinRM در ادامه جداگانه و فقط‌خواندنی انجام شد.
- Readback دیسک: `/` و Personal هرکدام حدود ۳۸ GiB آزاد دارند. Preview موجود Nuxt روی `127.0.0.1:4175` باقی است؛ ایمیج/کش Docker و خروجی‌های پروژه دست‌نخورده‌اند.
- بازآزمایی خودکار پاس شد: Web ‏۱۵/۱۵، MCP ‏۲۷/۲۷، Release ‏۱۰/۱۰ و lintهای Atomic/Profile. بیلد حجیم تازه تولید نشد.
- ممیزی رسمی مستندات Corevia Standards روی snapshot `f663ba2` برای ۵۱ فایل با Validate و Plan و بدون finding پاس شد؛ لینک‌های موقت برداشته شدند.
- refهای تازهٔ Standards/Bridge/Knowledge روی develop Fetch شدند (`f663ba2` / `7bb1645` / `e605a19`؛ main دانش `539b3e9`).
