# قرارداد پل Corevia Desk

لایه‌ی Nuxt و Adapter محلی MCP از یک بسته‌ی کوچک و نام‌دار برای درخواست‌ها
استفاده می‌کنند. تصمیم مجوز فقط در ACL Rust گرفته می‌شود. هیچ درخواستی به‌عنوان
دستور Shell، URL، SQL، عملیات Repository یا فراخوانی آزاد Rust تفسیر نمی‌شود.

## شکل اجرا

- Nuxt بسته‌ی `{ requestId, operation, payload, approvalReference? }` را می‌فرستد.
- Rust عملیات را از کاتالوگ مشخص پیدا می‌کند، فیلدهای لازم را بررسی می‌کند و
  بعد `src/corevia_acl.rs` را صدا می‌زند.
- پاسخ یکی از چهار حالت `accepted`، `denied`، `unsupported` یا `error` است.
- `accepted` یعنی ACL اجازه‌ی رفتن به مرحله‌ی Executor بومی را داده است؛ به‌معنی
  تمام‌شدن عمل سیستم‌عامل نیست.
- فقط شناسه‌ی Audit و کد خطای امن برمی‌گردد و Payload یا متن تأیید در خطاها
  ثبت یا بازتاب داده نمی‌شود.

Schema کامل در `docs/contracts/corevia-desk-bridge.schema.json` قرار دارد.

## محدودیت مرورگر و دسکتاپ

مرورگر معمولی به‌تنهایی نباید Capture صفحه، کنترل ورودی، مدیریت سرویس یا نشست
راه‌دور انجام دهد. بنابراین Nuxt برای داده‌های بومی تا زمان اجرای داخل WebView
دسکتاپ و تزریق پل Corevia Desk، وضعیت خالی و نیاز به Agent محلی را نشان می‌دهد.

Agent محلی باید فقط همین قرارداد را عرضه کند و خودش ACL Rust را صدا بزند؛ پورت
کنترل عمومی نباید ساخته شود. رابط فعال دسکتاپ Nuxt داخل WebView بومی Rust است.
منابع رابط قدیمی وارد Build یا Release فعال نیستند و قرارداد جدید به آن‌ها یا
به Bridge قدیمی وابسته نیست.
