# Adapter MCP برای Corevia Desk

این پوشه یک Adapter جداست، نه هسته‌ی Rust دوم. یک کاتالوگ کوچک از ابزارهای MCP
ارائه می‌کند و فقط عملیات نام‌دار را به پل محلی Rust می‌فرستد.

برای اجرای بسته‌بندی‌شده، `COREVIA_DESK_RUST_BRIDGE` را روی مسیر فایل اجرایی
Corevia Desk بگذار. Adapter آن را با `--corevia-mcp-bridge` اجرا می‌کند و از راه
stdio محلی، JSON خط‌به‌خط ردوبدل می‌کند. میزبان native هم می‌تواند
`createRustBridgeAdapter({ dispatch })` را با Binding محدود
`src/corevia_bridge.rs` تزریق کند. اگر هیچ‌کدام از این دو پل محلی وجود نداشته
باشد، پاسخ امن `local-agent-required` است.

این Adapter Shell اجرا نمی‌کند، پورت عمومی باز نمی‌کند، URL دلخواه را Proxy
نمی‌کند و به Repository یا SQL دسترسی ندارد. تصمیم نهایی هر درخواست با ACL Rust
است.

نسخه‌ی Customer Support فقط ابزارهای وضعیت، تنظیمات، تأیید اتصال ورودی و مجوز
اتصال را دارد. Full Desk ابزارهای اتصال خروجی و نشست را هم فهرست می‌کند.
ابزارهای حساس فیلد `approvalReference` از فراخواننده نمی‌پذیرند. پس از مذاکرهٔ
نسخهٔ پروتکل، Adapter فقط وقتی از قابلیت فرمِ درخواست تأیید MCP در خود کلاینت
پشتیبانی شود، برای هر درخواست حساس تأیید جداگانه می‌گیرد؛ رد/لغو، timeout، نسخهٔ
قدیمی یا نبود این قابلیت باعث رد امن می‌شود. پاسخ تأیید به امضای داخلی محدود به
عملیات و دادهٔ همان درخواست تبدیل می‌شود و Rust آن را یک‌بارمصرف بررسی می‌کند.
کلاینت واقعی TypeScript MCP SDK از مسیر stdio با helperهای بومی آزموده شد:
کاتالوگ Full Desk شامل ۲۵ ابزار و پنج Read امن، و کاتالوگ Customer Support
شامل ۹ ابزار و چهار Read امن بود. این فقط سازگاری خواندنی با کلاینت است، نه
تست Host واقعیِ دارای elicitation. تأیید/رد/لغو/timeout عملیات حساس و برخی
اجراگرهای Toolbox هنوز بازند. Readهای امن همچنان از ACL Rust پیروی می‌کنند.

اگر Rust درخواست را مجاز کند اما نتیجهٔ بومی `executed: false` باشد، Adapter آن
را در MCP به‌صورت خطا گزارش می‌کند؛ مجازشدن درخواست به معنای اجرای موفق ابزار نیست.
این رفتار، نبود اجراگرهایی مثل Camera/Printer/Service را رفع نمی‌کند و فقط جلوی
نمایش موفقیت گمراه‌کننده را می‌گیرد.
ارسال پیام از `send_chat` نیز برای هر پیام تأیید جداگانه می‌گیرد و متن پاک‌سازی‌شده
را پیش از اجرا به کاربر نشان می‌دهد.
ابزار هدایت پورت `remoteHost` اختیاری می‌پذیرد؛ اگر تعیین نشود، مقصد loopback
`127.0.0.1` است. مقدار میزبان محدود و پیش از اجرا اعتبارسنجی می‌شود؛ تأیید جداگانهٔ
هر فراخوانی همچنان لازم است و این بررسی جای آزمون تونل زنده را نمی‌گیرد.
ابزار `use_voice_call` نیز فیلد اختیاری Boolean به نام `enabled` دارد تا درخواست
شروع یا توقف تماس صریح باشد؛ پل Native مقدار غیر Boolean را رد می‌کند و تست این
قرارداد به‌تنهایی اثبات تماس صوتی زنده نیست.
